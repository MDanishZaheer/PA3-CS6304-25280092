# Task 1: Colab execution and local replay

`main_task_1.ipynb` runs the fixed Task 1 protocol in Colab. Locally, the same stepwise notebook reads completed Colab outputs from `Task_1/results/` and rebuilds the RQ1–RQ5 evidence without training or GPU evaluation.

## Upload and run

1. Upload this `Task_1` folder, including its small `assets/times.ttf` figure font, to `MyDrive/ATML_PA3/Task_1/`. Do not upload `Data/`, model weights, or earlier result archives. Keep the folder name and path exact, or edit `DRIVE_TASK_ROOT` in the notebook. The font is Git-ignored; it is needed for exact Times New Roman figure text on Colab.
2. The supplied `first_plot_questions.yaml` is in `Task_1/data/`. Upload it with the folder. The notebook copies it to its configured `Data/Task_1/` runtime path and keeps the JSON variants' system instructions separate from the user prompts.
3. Open `main_task_1.ipynb` from Drive in Colab. Select an **L4 GPU** and **High RAM**, then choose **Run all**. The first cells mount Drive, copy the code to `/content/Task_1`, install dependencies, and check GPU, RAM, and free disk. Data and the Qwen model download into `/content/Data/Task_1`.
4. Results are produced in `/content/Task_1/results` and copied to `MyDrive/ATML_PA3/Task_1/results/`. The notebook refuses to restore an older unmarked results folder, so remove or move any previous Kaggle `Task_1/results/` on Drive before the first run. Each checkpoint is hashed and backed up as soon as its optimizer update completes. The notebook stops near its session reserve and saves a recovery checkpoint. If a session ends, start a new L4/High RAM runtime and choose **Run all** again. It restores the latest checkpoint for each method and the Full FT midpoint. It then resumes the first unfinished method or evaluation task. Colab hardware availability and maximum session duration can vary; one uninterrupted run is not guaranteed.
5. Check `Task_1/results/metrics/*_resources.json` for `completed_updates: 1250` on all five methods. Check that the seven `*_benchmarks.json` files each contain four task results. The final RQ tables and 300 dpi PNG plots are in `Task_1/results/metrics/` and `Task_1/results/figures/`.

The notebook trains Full FT, Full FT with L2-SP, LoRA rank 4, LoRA rank 16, and OPLoRA rank 16. It keeps checkpoints at updates 312, 625, 937, and 1250 in Drive. Colab VM scratch retains only the latest method checkpoint and Full FT update 625 after each verified backup, so local disk does not accumulate every large checkpoint. The Drive `Task_1/results/` folder is the durable copy, with `checkpoints/`, `histories/`, `metrics/`, `predictions/`, `annotations/`, and `figures/` beneath it.

## Rebuild evidence locally

The compact evidence committed under `Task_1/results/` is sufficient for local replay. For a separate full Colab download, copy `metrics/`, `histories/`, `predictions/`, and `annotations/` into local `Task_1/results/`; the notebook derives a compact paired GSM8K score file from the full predictions if needed. Checkpoints are optional for this evidence-only step. Open the notebook with the `ATML` Conda kernel and choose **Run all**. It detects the local kernel, checks the saved Colab files, displays each completed training and evaluation stage, and rebuilds the research-question tables and figures. It neither downloads models nor repeats training, scoring, diagnostics, or qualitative generation. The saved Colab origin and hardware are shown explicitly. A missing result produces an error instead of silently displaying an incomplete report.

To repeat evaluation or diagnostics, keep the final checkpoints, Full FT update 625, and the pinned source revisions. Repeating evaluation does not repeat training. The qualitative annotation sheet has 42 rows. The completed `annotations/qualitative_42_review.csv` is used for the RQ5 summary when present; otherwise, fill the blank sheet's binary fields with `0` or `1` and rerun the RQ5 cells.

The fixed data selection, model settings, optimization, checkpoint updates, and task definitions are in `configs/base.yaml` and the method YAML files. Git includes compact metrics, histories, annotations, qualitative responses, and report figures. Downloaded data, recovery checkpoints, and large per-example benchmark exports are ignored. Source revision pins and selected training IDs are saved with results, so resumed sessions check the same inputs.
