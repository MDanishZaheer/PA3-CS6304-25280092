## Protocol and attribution

The split seed, 200/800 split, ten candidate orders, fixed budgets, adaptive threshold grid, 1,000 question-level bootstrap draws, and live generation settings are validated or recorded in `configs/base.yaml` and the manifest. Gold answers are used to grade and analyze outcomes; candidate grouping, ranking, voting, and stopping use only revealed candidates. The offline generated-token sum is a cost proxy and excludes prompt prefill, attention collection, and scoring time.

The code uses the `math-verify` package for MATH equivalence, Hugging Face Transformers for the pinned Qwen model, and the official MathVista released metadata and normalization conventions. The MathVista choice, numeric, and precision behavior follows the released evaluator at <https://github.com/lupantech/MathVista/blob/main/evaluation/calculate_score.py>, with the assignment-required exception that missing extractions always remain one incorrect `NO_ANSWER` group. The MathVista metadata source is <https://github.com/lupantech/MathVista/blob/main/data/testmini.json>. These are library and protocol references; no external training code is copied.
